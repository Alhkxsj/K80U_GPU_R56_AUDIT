# final_report — 最终审计报告

## 目的

对外交付的唯一结论出口。读者是决策者与工程负责人，不假设其读过 `03`–`06` 的过程材料。

## 报告结构（建议）

```markdown
1. 执行摘要
   - 结论（可行 / 有条件可行 / 不可行）
   - 三条关键依据
   - 建议的下一步与所需资源量级

2. 审计范围与方法
   - 标的：MT6991 / Immortalis-G925 MC12 / Android 17 / 原厂 Linux 6.6.118（运行时为第三方 6.6.143）/ R56p0
   - 边界：审计了什么，没审计什么
   - 证据等级说明

3. 现状基线
   - 出厂 kbase / firmware / userspace 版本三元组
   - 平台适配层概况

4. 差异分析结论
   - kbase 差异（引用 03 的条目 ID）
   - 平台层差异（引用 04）
   - ABI 匹配性（引用 05）

5. 方案比选与推荐
   - 四方案对比表
   - 推荐路线与理由
   - 工作量估算与关键路径

6. 风险与前置条件
   - 高风险项 Top N
   - 必须先行闭环的前置条件

7. 验证与回滚
   - 分层验证判定标准
   - 回滚路径

8. 附录
   - 证据索引（结论 ↔ 文件/行号/版本）
   - 术语表
```

## 写作要求

1. **结论前置**：第 1 节必须能在不阅读后文的情况下支撑决策。
2. **证据可点开**：所有关键判断附 `03`–`06` 的条目 ID 或文件路径。
3. **区分事实与推断**：推断必须显式标注"推断"及其依据强度。
4. **不隐藏不确定性**：无法闭环的问题列入"未解决项"，并说明其对结论的影响。
5. **不夸大**：不使用"完全兼容""彻底解决"等无法证伪的表述。
