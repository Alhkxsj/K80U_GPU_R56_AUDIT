# 01_original_baseline — 原厂基线快照（只读）

## 目的

冻结设备**出厂状态**的 GPU 相关事实，作为全部差异比对与回归判断的零点。本目录的内容是"事实"，不是"意见"。

## 本目录的核心约束

> **一旦落盘即冻结。** 不允许格式化、不允许补注释、不允许"顺手修一下"。任何改动只能以 patch 形式提交到 `03`–`06`。

## 需要采集的基线对象

| 维度 | 采集内容 | 建议形式 |
| --- | --- | --- |
| kbase 版本 | `MALI_RELEASE_NAME`、`BASE_KERNEL_VERSION`、分支/commit、编译时间 | 文本快照 |
| 模块元数据 | `*.ko` 的 `modinfo`（vermagic、依赖、签名状态）、模块大小与 SHA256 | 文本 + 校验和 |
| 内核配置 | GPU 相关 `CONFIG_*`（mali/kbase/base、CSF、电源、调试） | 配置摘录 |
| 平台描述 | GPU 相关 DTS/DTSI 节点（`mfg*`、`gpu*`、电源域、时钟、OPP 表） | 源文件快照 |
| 固件 | CSF firmware 文件名、版本、大小、SHA256、加载路径 | 清单（实体另存） |
| 用户态 | `libGLES_mali.so` 等 blobs 的版本串、大小、SHA256、所在分区 | 清单（实体另存） |
| 运行时事实 | 开机后 GPU 节点、驱动版本节点、devfreq 档位（如可获取） | 只读采集记录 |

## 目录内文件规划

```
01_original_baseline/
├── README.md
├── MANIFEST.md              # 每个文件的来源、采集方式、采集时间、SHA256
├── version/                 # 版本与元数据文本快照
├── config/                  # 内核配置摘录
├── dts/                     # GPU 相关设备树快照（原样）
└── firmware_userspace/      # 固件与用户态清单（大文件只登记不存实体）
```

## 准入标准

1. 每份快照都能回答"何时、从哪、以何方式"采集。
2. 二进制类对象必须带 SHA256，且与 `MANIFEST.md` 记录一致。
3. 快照必须保持原始格式（不重排版、不裁剪字段），必要时附"截取范围说明"。

## 完成标准

- §"需要采集的基线对象"表中每一行都有对应证据或明确的"不可获取 + 原因"。
- 版本三元组（kbase / firmware / userspace）首次形成闭环记录。

## 与相邻目录的边界

- 本目录**只陈述现状**；"现状有什么问题"写在 `03`/`04`。
- 与 `02_r56_source/` 的关系：两者都是只读原树，但 `01` 是设备出厂态，`02` 是上游目标态，禁止互相覆盖。

## 风险点

- 设备若已被改动（root、刷入第三方模块），"出厂基线"可能已不可得，必须在 `MANIFEST.md` 中显式标注可信度。
- 用户态 blobs 与固件可能受分区校验保护，采集需只读方式进行，禁止写入设备。
