# DECISION_LOG — 项目决策日志

> 本文件记录**已经形成**的决策，供后续 Agent 判断"哪些事已有定论、哪些还能改"。
>
> 每条决策包含：ID、决策内容、背景、证据来源、证据等级、当前状态、是否允许重新审议。
>
> **原则**：推断不得伪装成决策。凡证据不足者，状态标 `待执行` 或 `条件性生效`，并在"再审议"列写明触发条件。

| 字段 | 取值约定 |
| --- | --- |
| 状态 | `生效`（已定，按此执行） / `生效（条件性）`（有前提，前提变化需复审） / `待执行`（已决定但尚未落地） / `已被取代`（保留历史） |
| 再审议 | `否`（属项目定义，不可改） / `需用户授权` / `新证据即可`（Agent 可依新证据提出修订） |

## B. 证据治理类

### D-005 · 第三方 GKI 与原厂 boot 的运行时证据必须分开

| 项 | 内容 |
| --- | --- |
| **决策** | 设备当前运行**第三方 GKI 内核**（KernelSU + SUSFS），其运行时观测一律记 **[D·B]**，**不得**表述为"原厂环境实测"或"出厂状态验证" |
| **背景** | Stage 4 首轮把全部设备观测一律记作"真机实测/出厂状态"，掩盖了内核来源差异。证据显示 `id` 输出 `context=u:r:ksu:s0`，该 SELinux 域只在 KSU 补丁内核存在 |
| **证据来源** | `05_userspace_firmware/08_kernel_provenance_audit.md` §1、§2.3；`07_device_evidence.md` §2；根 `README.md` §7 第 5 项 |
| **证据等级** | **[D·B]**（SELinux 域）+ **[B]**（CI 运行页） |
| **状态** | 生效 |
| **再审议** | 新证据即可（若设备恢复原厂 boot 并重采，则新增 [D·B-原厂] 记录，**不删除**现有记录） |

### D-006 · A / B / C 三类设备证据归属规范

| 项 | 内容 |
| --- | --- |
| **决策** | 设备证据按来源三分：**A** 厂商分区静态文件（`/vendor`、`/vendor/firmware`）→ **[D·A]**；**B** 第三方内核运行时状态（`uname`/`lsmod`/`/sys/module`/`/dev/mali0`/dmesg/服务）→ **[D·B]**；**C** 厂商内核模块文件与装载状态 → **[D·C]**。三者不可互相替代。 |
| **背景** | 三类证据的**可信边界不同**：A 类不受内核替换影响，B 类受第三方补丁影响，C 类只证明"文件存在/可装载"不证明"同源" |
| **证据来源** | `05/08` §2.1–§2.5；`AGENTS.md` §0.6 |
| **证据等级** | — （方法论规则） |
| **状态** | 生效 |
| **再审议** | 新证据即可（如需增加 D 类，须先说明其不可归入 A/B/C 的理由） |

### D-007 · 仓库 `.ko` 与设备 `.ko` 不是同一构建

| 项 | 内容 |
| --- | --- |
| **决策** | 仓库 `01_original_baseline/kernel_ref_mt6991/vendor_dlkm/` 的 15 个 `.ko` 与设备实际装载的 GPU 模块**不是同一二进制**，只共享源码标签 `r49p1-03bet0`。禁止用"模块装载成功"推断"与仓库同源"。 |
| **背景** | vermagic 决定性判据：仓库为 `6.6.118-…-g57e634f35c1b`，运行内核为 `6.6.143-…-gf9aa2fec23c3`；`ged` 体积 1,093,352 B（仓库）vs 684,032 B（设备 `lsmod` 报值）。同名同版本串 ≠ 同构建。 |
| **证据来源** | `05/08` §3.1、§3.2；`05/01` §2.1；`01_original_baseline/MANIFEST.md` |
| **证据等级** | **[E1]**（vermagic 字符串）+ **[E2]**（体积差 409 KB 交叉印证） |
| **状态** | 生效 |
| **再审议** | 新证据即可（若取得设备 `.ko` 的 SHA256 且与仓库一致，则本条被推翻，需重写） |

### D-008 · R56p0「只换内核 + 保留原厂固件」存在严格 header 版本风险

| 项 | 内容 |
| --- | --- |
| **决策** | 组合 B（R56p0 Kbase + 原厂 CSF 固件 + 原厂用户态）**判定为不可行**，理由：`FIRMWARE_HEADER_VERSION_MINOR` 在两版加载器中为 **3 vs 4**，r56p0 用 `!=` **严格相等**校验、无兼容分支、无 fallback。 |
| **背景** | 这是 Stage 4 最重要的单点判据——一行差异否决整个组合，无需讨论后续层次 |
| **证据来源** | `05/02` §3.1（`r56p0 csf/mali_kbase_csf_firmware.c:2698`、`r49p1 :108-109`）；`05/06` §2.2 |
| **证据等级** | **[E1]**（源码确定）+ **[E2]**（原厂固件实际值由启动一致性推理指向 0.3） |
| **状态** | **生效（条件性）**：**源码判据成立**；**原厂固件实际字节仍为 [U]**（U4-01），故"实测判据"未闭合 |
| **再审议** | 新证据即可（若 `od -N 8` 显示 `04 00`，则组合 B 的否决被**推翻**，须重写 `02`/`06`） |

### D-009 · 用户态契约层兼容 ≠ 实现层运行兼容

| 项 | 内容 |
| --- | --- |
| **决策** | "原厂用户态可保留"只能表述为**契约层兼容候选**（[E1] 支撑：ioctl 28/28、结构体 30/30、属性 83/83、能力表保留 ≤1.30 语义、`min()` 夹取），**不得**表述为"已实测可用" |

| **证据来源** | `05/03` §12；`05/06` §2.3；`05/07` §8 |
| **证据等级** | **[E1]**（契约）+ **[U]**（实现） |
| **状态** | 生效 |
| **再审议** | 新证据即可（取得 DDK 版本串与 `strace` 后可将 U4-04 推进/闭合） |
