# 00_reference — 参考资料与规范登记册

## 目的

集中登记本次审计所依赖的**上游权威资料**，作为一切技术判断的引用基准。本目录只回答"依据是什么"，不存放分析结论，也不存放厂商私有交付物（后者在 `01`/`02`）。

## 收录范围

| 类别 | 具体对象（示例，实际以登记为准） |
| --- | --- |
| Arm GPU 交付物文档 | Mali GPU DDK R56p0 Release Notes、kbase 集成指南（Integrator's Guide）、CSF 架构说明 |
| Arm 接口规范 | kbase 内核↔用户态 ioctl ABI、CSF firmware 接口、GPU 电源/时钟控制模型 |
| 平台方文档 | MediaTek MT6991 BSP 中 GPU（mfg / mali / gpu）章节、平台电源域与 OPP 说明 |
| Android 侧要求 | Android 17（SDK 37）对 vendor 模块、内核模块、VINTF 的相关约束 |
| 内核侧要求 | Linux 6.6 / GKI KMI、模块签名与 vermagic 规则 |
| 已知问题 | 与 Mali CSF / MTK GPU 相关的 errata、CVE、上游修复记录 |

## 不收录

- 任何 Arm/MTK 的私有源码或二进制（→ `02_r56_source/`、`01_original_baseline/`）
- 本项目的推导、对比、结论（→ `03`–`06`）
- 第三方博客/论坛等非权威材料；如确需引用，必须标注"非权威，仅作线索"并单列

## 目录内文件规划

```
00_reference/
├── README.md                 # 本文件
├── MANIFEST.md               # 资料清单：标题 / 来源 / 版本 / 生效日期 / 获取方式
├── REFERENCE_INDEX.md        # 引用索引：审计结论 ↔ 资料条目 的映射
└── notes/                    # 单篇资料摘要（可选，一资料一文件）
```

## 准入标准

一条资料进入登记册，必须同时具备：

1. **可定位**：有明确标题、版本或文档编号、发布方。
2. **可获取**：有稳定获取路径（链接或本地存放位置），且记录获取日期。
3. **有适用范围**：标明适用的 SoC / 驱动版本 / Android 版本，避免跨版本误用。

## 完成标准

- `REFERENCE_INDEX.md` 中每条被引用的资料均可解析到 `MANIFEST.md` 的条目。
- 无"来源不明"条目。

## 与相邻目录的边界

- 这里放**外部权威依据**；`03`–`06` 放**基于依据的推导**。
- 若发现 Arm 文档与 MTK 实际实现对不上，该冲突记录在 `04_mtk_platform/`，不在本目录裁决。

## 风险点

- Arm DDK 文档通常随交付物一同提供且不公开分发，需确认合法获取渠道与引用范围。
- MTK BSP 文档版本与设备实际固件版本可能不一致，登记时必须记录"文档版本 ≠ 设备版本"的可能性。
