# 02_r56_source — R56p0 上游源码（只读原树）

## 目的

存放 Arm Mali GPU DDK **R56p0** 的原始交付源码树，作为"目标态"的唯一权威副本。本目录保持**与交付物逐字节一致**，不编译、不配置、不打补丁。

## 收录内容

| 组件 | 说明 |
| --- | --- |
| `kernel/`（kbase） | Mali 内核驱动主树，CSF（5th Gen）路径相关实现 |
| `kernel/drivers/gpu/arm/` | 若交付物按此布局组织，保持原结构不重排 |
| 构建描述 | `Kbuild` / `Makefile` / `Kconfig` / 配置模板（原样保留） |
| 文档 | 交付物自带 README、Release Notes、集成说明（若有） |
| 固件 | 若交付物内含 CSF firmware，原样保留并单独登记 |

## 禁止事项

- ❌ 不执行 `make`、不生成 `.config`、不产出 `.o`/`.ko`
- ❌ 不打任何补丁，不做代码格式化，不做换行符转换
- ❌ 不删除"看起来无用"的平台目录（后续比对需要完整性）
- ❌ 不用本目录的树直接覆盖 `01_original_baseline/` 中的任何文件

## 目录内文件规划

```
02_r56_source/
├── README.md
├── MANIFEST.md          # 交付物名称、版本串、获取渠道、解包日期、逐项 SHA256
├── SOURCE_TREE.md       # 顶层结构说明（与原树一致，不改动原文件）
└── mali_r56p0/          # 原始交付源码树（只读）
```

## 准入标准

1. 版本可信：能证明是 **R56p0**（Release Notes 或源码内版本宏），而非 R55/R57 或分支快照。
2. 完整性可验：解包后关键路径（kbase 主目录、CSF 相关文件）齐全，`MANIFEST.md` 记录总文件数与校验和。
3. 来源可溯：记录获取渠道与时间；若为内部交付，记录交付单号。

## 完成标准

- 能回答"R56p0 的 kbase 版本宏取值是多少"这一具体事实。
- 能列出 R56p0 中与 5th Gen / CSF 相关的目录与关键文件清单（供 `03_kbase_csf/` 引用）。

## 与相邻目录的边界

- **`02` 是原树，`03` 是分析**。所有"R56p0 里这个函数怎么实现的"讨论写进 `03_kbase_csf/` 并引用 `02` 的路径与行号。
- 与 `01` 的关系：`01` 是现有设备跑的东西，`02` 是想要跑的东西；比对结论不属于本目录。
