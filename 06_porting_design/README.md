# 06_porting_design — 移植方案设计与风险登记

## 目的

把 `03`–`05` 的事实汇总成**可决策的方案**：走哪条路线、代价多大、风险在哪、失败怎么退。本目录是唯一允许写"结论"的分析目录。

## 候选路线

| 路线 | 做法 | 主要优点 | 主要代价 |
| --- | --- | --- | --- |
| **A. 整包替换** | 用 R56p0 原树编译，重做 MTK 平台适配 | 代码最新、与上游一致 | MTK 私有改动需全部重写；风险最高 |
| **B. 以 MTK 为底回移**（默认倾向，待论证） | 保留出厂 BSP 结构，把 R56p0 的必要变更以补丁回移 | 改动面小、可增量验证、易回滚 | 需精确识别"必要变更"，存在遗漏风险 |
| **C. 仅升级固件/用户态** | 内核不动，替换 CSF firmware 与 blobs | 风险最低、不触碰内核 | 受 ABI 窗口限制，可能完全不成立 |
| **D. 不移植** | 维持出厂驱动 | 零风险 | 放弃 R56p0 的收益 |

> 倾向 B 的理由：Android 16 / GKI 6.6 对内核模块有符号与版本约束，A 路线需同时解决平台适配与构建合规两件事，爆炸半径过大。此倾向**必须**在方案比选中用 `03`/`04` 的数据正式论证，不得直接采信。

## 风险登记册字段

| 字段 | 说明 |
| --- | --- |
| ID | `R-001` 起 |
| 类别 | 技术 / 平台 / ABI / 合规 / 进度 |
| 描述 | 具体到可观察的失败现象 |
| 影响 | 高/中/低 + 说明 |
| 可能性 | 高/中/低 |
| 触发条件 | 什么情况下会发生 |
| 缓解措施 | 降低可能性或影响的手段 |
| 验证方式 | 如何证明缓解有效 |
| 状态 | 未验证 / 已验证 / 已关闭 |

## 验证计划的层级（不得跳层）

1. **构建层**：模块可编译、符号可解析、无未定义引用
2. **加载层**：模块可插入、初始化完成、无 oops
3. **固件层**：CSF firmware 加载成功、版本协商通过
4. **基础功能层**：GPU 节点可用、简单分配/映射正常
5. **渲染层**：EGL/GLES 上下文可用、离屏渲染正确
6. **合成层**：屏幕正常显示、无花屏/闪屏
7. **稳定性层**：压力与长时间运行、挂起恢复、异常注入

> 本项目当前阶段仅做**可行性审计**，上述验证在方案获批并进入实施阶段后执行；本阶段只定义判定标准，不执行。

## 完成标准

- 每个方案都有明确的工作量量级与阻塞项，不存在"待定"占位。
- 每条风险都能映射到 `03`/`04`/`05` 中的具体证据或明确的"未知"。
- 给出明确结论：**可行 / 有条件可行（附条件）/ 不可行**，并说明推翻该结论需要什么新证据。

## 与相邻目录的边界

- 本目录**引用**事实，不**生产**事实；发现新事实要回写到 `03`–`05` 并在此引用其 ID。
- 最终对外的结论性表述放 `final_report/`，本目录保留完整推理过程。
