# 05_userspace_firmware — 用户态组件与 CSF 固件

## 目的

覆盖"内核之外"的两段：**CSF firmware** 与 **用户态图形栈**。Mali 5th Gen 的实际调度大量下沉到固件，用户态又与内核存在版本协商，因此这条链路是"驱动换了但屏幕不亮"的高发区。

## 分析对象

### 固件侧

| 项 | 关注点 |
| --- | --- |
| CSF firmware | 文件名、版本串、大小、SHA256、目标 GPU 型号与 core 配置匹配性 |
| 加载链路 | 由谁加载（内核 / vendor init / 平台服务）、路径、权限、校验 |
| 版本协商 | 固件与 kbase 的接口版本窗口，是否强绑定 |

### 用户态侧

| 项 | 关注点 |
| --- | --- |
| GLES / Vulkan | `libGLES_mali.so`、Vulkan 驱动（若有）版本与内核 ABI 匹配性 |
| 缓冲区通路 | gralloc / mapper / 分配器与 GPU 内存属性的接口一致性 |
| 合成器 | HWC / composer 对 GPU 的依赖点与格式支持 |
| 版本协商 | 用户态探测内核版本的机制，以及不匹配时的降级/拒绝行为 |
| 其它 | devfreq 用户态策略、GPU 相关系统属性与服务 |

## 核心判据：ABI 三元组

> **kbase 版本 · CSF firmware 版本 · 用户态 blobs 版本** 必须作为整体评估。

评估矩阵（在 Stage 4 填写实际值）：

| 组合 | kbase | firmware | userspace | 预期结果 |
| --- | --- | --- | --- | --- |
| 现状 | 出厂 | 出厂 | 出厂 | 正常 |
| 仅换内核 | R56p0 | 出厂 | 出厂 | 大概率不可用（版本协商失败） |
| 换内核+固件 | R56p0 | R56p0 | 出厂 | 待验证（用户态 ABI 是否兼容） |
| 全量替换 | R56p0 | R56p0 | R56p0 | 理论自洽，但受分区/签名/合规约束 |

## 准入标准

1. 每个二进制组件都带 SHA256 与版本串（从文件内部提取，而非仅凭文件名）。
2. 版本协商机制必须有代码或行为层面的依据（哪个文件、哪段逻辑、失败表现），不接受"应该会检查"。
3. 明确标注每个组件的**可替换性**：可否单独替换、替换后受哪些校验约束。

## 完成标准

- ABI 矩阵四行全部有结论，且每行附依据。
- 能回答：是否存在"只换内核 + 固件、复用出厂用户态"的可行窗口。

## 与相邻目录的边界

- 接口**定义**在 `03_kbase_csf/abi/` 维护；本目录只做**匹配性判定**。
- 合规与法律风险（再分发厂商 blobs）最终在 `06_porting_design/` 的风险登记册中汇总。
